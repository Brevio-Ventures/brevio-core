# R6.5: Post-incident regression crystallization

Group: Testing and hermeticity. Generated from the rule definitions; do not edit by hand.

## What it catches

Post-incident regression crystallization: every bug fix includes a failing-first test.

## Why

A bug without a test comes back.

## A bad example

```
fix: handle empty cart   (no test)
```

## A good example

```
fix: handle empty cart   (adds a test that fails without the fix)
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
