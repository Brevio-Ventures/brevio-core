# R6.5: Post-incident regression crystallization

**Short answer:** Every bug fix includes a failing-first test. A bug without a test comes back.

Group: Testing and hermeticity. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Post-incident regression crystallization: every bug fix includes a failing-first test.

## Why

A bug without a test comes back.

## A bad example

```
fix: handle empty cart   (no test)
```

## A good example

```
fix: handle empty cart   (adds a test that fails without the fix)
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R6.5 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
