# R13.5: Standard log severity

**Short answer:** Use debug/info/warn/error appropriately without log spam. If everything is an error, nobody reads the errors.

Group: Observability and logging. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Standard log severity: use debug/info/warn/error appropriately without log spam.

## Why

If everything is an error, nobody reads the errors.

## A bad example

```ts
log.error('request received');
```

## A good example

```ts
log.debug('request received');
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R13.5 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
