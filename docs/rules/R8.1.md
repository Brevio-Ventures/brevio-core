# R8.1: Anti-cloaking & markdown parity

Group: Marketing and attribution. Generated from the rule definitions; do not edit by hand.

## What it catches

Anti-cloaking & markdown parity: serve identical facts to crawlers and browsers.

## Why

Showing a crawler different facts than a person is cloaking. Search engines penalise it.

## A bad example

```ts
if (isBot(ua)) return richPage; else return thinPage;
```

## A good example

```ts
return samePage;
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
