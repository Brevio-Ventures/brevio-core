# R4.3: N+1 query prevention

Group: Database and migrations. Generated from the rule definitions; do not edit by hand.

## What it catches

N+1 query prevention: batch queries with IN / joins instead of per-row loop queries.

## Why

One query per row turns a page of 100 rows into 101 round trips.

## A bad example

```ts
for (const u of users) await db.orders.where({ userId: u.id });
```

## A good example

```ts
await db.orders.where({ userId: { in: users.map((u) => u.id) } });
```

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.
