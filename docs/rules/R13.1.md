# R13.1: Zero secret logging

Group: Observability and logging. Generated from the rule definitions; do not edit by hand.

## What it catches

Zero secret logging: redact passwords, tokens, API keys, and authorization headers.

## Why

A secret in a log or in code ends up in every place the log goes.

## A bad example

```ts
const apiKey = 'xxxxxxxxxxxxxxxxxxxx';
```

## A good example

```ts
const apiKey = process.env.PAYMENT_KEY;
```

## How it is checked

- A diff scan of added lines (`code_rules.scan_added_lines_for_rules`).

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

What the scanner already leaves alone: A line that contains the word 'example' or 'test' is not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
