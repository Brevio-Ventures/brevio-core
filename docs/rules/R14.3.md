# R14.3: Token expiration bounding

Group: Auth and sessions. Generated from the rule definitions; do not edit by hand.

## What it catches

Token expiration bounding: short-lived access tokens paired with rotating refresh tokens.

## Why

A long-lived token that leaks stays useful for months.

## A bad example

```ts
sign(payload, key, { expiresIn: '365d' })
```

## A good example

```ts
sign(payload, key, { expiresIn: '15m' })  // plus a rotating refresh token
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
