# R4.1: Expand-contract migrations

Group: Database and migrations. Generated from the rule definitions; do not edit by hand.

## What it catches

Expand-contract migrations: additive nullable/default columns; no single-step drop/rename.

## Why

A one-step drop breaks the old code that is still running during the deploy.

## A bad example

```sql
ALTER TABLE users DROP COLUMN name;
```

## A good example

```sql
ALTER TABLE users ADD COLUMN full_name text NULL;  -- drop 'name' in a later release
```

## How it is checked

- A one-line card in the prompt of a slice that touches matching files (`dev_rules.slice_micro_rules`).

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
