# R4.2: Foreign-key & tenant composite indexing

Group: Database and migrations. Generated from the rule definitions; do not edit by hand.

## What it catches

Foreign-key & tenant composite indexing: index FKs and (tenant_id, created_at).

## Why

A foreign key without an index makes every join and every tenant list a full scan.

## A bad example

```sql
ALTER TABLE a ADD COLUMN tenant_id uuid REFERENCES t(id);
```

## A good example

```sql
ALTER TABLE a ADD COLUMN tenant_id uuid REFERENCES t(id);
CREATE INDEX a_tenant_created ON a (tenant_id, created_at);
```
