# R3.2: Monetary integer representation

Group: Billing and money. Generated from the rule definitions; do not edit by hand.

## What it catches

Monetary integer representation: store money as integer minor units (cents) + currency.

## Why

A float cannot hold 0.1 exactly, so sums of money drift by a cent.

## A bad example

```ts
const price = amountCents / 100;
```

## A good example

```ts
const priceCents = amountCents;  // format when you show it
```

## How it is checked

- A pre-flight scan of added lines (`dev_rules.scan_added_lines`).
- A one-line card in the prompt of a slice that touches matching files (`dev_rules.slice_micro_rules`).

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

What the scanner already leaves alone: A file named format* or display*, a component, a function named format*/display* and a line that calls Intl.NumberFormat, toLocaleString or toFixed are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
