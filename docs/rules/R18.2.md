# R18.2: Form control labels

**Short answer:** Every input, select, and textarea element has associated label. An input with no label cannot be named by a screen reader or clicked by its label.

Group: Accessibility (WCAG 2.1 AA). Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Form control labels: every input, select, and textarea element has associated label.

## Why

An input with no label cannot be named by a screen reader or clicked by its label.

## A bad example

```tsx
<input type="email" />
```

## A good example

```tsx
<label htmlFor="email">Email</label>
<input id="email" type="email" />
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R18.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
