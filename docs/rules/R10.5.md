# R10.5: Response size bounding

Group: API and network robustness. Generated from the rule definitions; do not edit by hand.

## What it catches

Response size bounding: clamp response body reads to avoid unbounded buffer allocation.

## Why

Reading a response without a cap lets one big reply use all the memory.

## A bad example

```ts
const text = await res.text();
```

## A good example

```ts
const text = await readCapped(res, 1_000_000);
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
