# R10.1: Explicit HTTP request timeouts

**Short answer:** Every fetch/axios call specifies timeout or AbortSignal. A request with no timeout can hang a worker for ever.

Group: API and network robustness. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Explicit HTTP request timeouts: every fetch/axios call specifies timeout or AbortSignal.

## Why

A request with no timeout can hang a worker for ever.

## A bad example

```ts
await fetch(url);
```

## A good example

```ts
await fetch(url, { signal: AbortSignal.timeout(5000) });
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R10.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
