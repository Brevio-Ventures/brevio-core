# R12.8: No unbounded collection growth

Group: Memory and resource leaks. Generated from the rule definitions; do not edit by hand.

## What it catches

No unbounded collection growth: caches and registries specify TTL or LRU eviction.

## Why

A cache with no limit grows for the life of the process.

## A bad example

```ts
const cache = new Map();
```

## A good example

```ts
const cache = new LRU({ max: 500, ttl: 60_000 });
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
