# R9.1: No untyped escape hatches

Group: Type safety. Generated from the rule definitions; do not edit by hand.

## What it catches

No untyped escape hatches: no `as any` casts or `z.any()` schemas in production source.

## Why

`any` turns the type checker off for everything it touches.

## A bad example

```ts
const user = (await res.json()) as any;
```

## A good example

```ts
const user = UserSchema.parse(await res.json());
```

## How it is checked

- A diff scan of added lines (`code_rules.scan_added_lines_for_rules`).
- A one-line card in the prompt of a slice that touches matching files (`dev_rules.slice_micro_rules`).

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

What the scanner already leaves alone: Test files, test helpers and setup files, and comment lines are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
