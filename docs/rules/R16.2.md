# R16.2: No wildcard dependency versions

**Short answer:** Package.json avoids '*' or unbounded range dependencies. A wildcard version takes whatever was published last, including a bad release.

Group: Supply chain. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No wildcard dependency versions: package.json avoids '*' or unbounded range dependencies.

## Why

A wildcard version takes whatever was published last, including a bad release.

## A bad example

```json
"left-pad": "*"
```

## A good example

```json
"left-pad": "1.3.0"
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R16.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
