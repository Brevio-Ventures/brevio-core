# R17.8: Route handler return typing

Group: React and Next.js patterns. Generated from the rule definitions; do not edit by hand.

## What it catches

Route handler return typing: route handlers return typed NextResponse with status.

## Why

An untyped handler returns whatever it returns, with a status nobody chose.

## A bad example

```tsx
export async function GET() { return Response.json(data); }
```

## A good example

```tsx
export async function GET(): Promise<NextResponse<Data>> { return NextResponse.json(data, { status: 200 }); }
```

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
