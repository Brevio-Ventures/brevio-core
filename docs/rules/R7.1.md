# R7.1: Contract-first monorepo changes

Group: Architecture and contracts. Generated from the rule definitions; do not edit by hand.

## What it catches

Contract-first monorepo changes: update shared Zod/OpenAPI schema before consumers.

## Why

If a consumer changes first, the contract and the code disagree until the next release.

## A bad example

```
change the API handler, then edit the shared schema later
```

## A good example

```
edit the shared schema, then the handler and the client in the same change
```

## How it is checked

- A one-line card in the prompt of a slice that touches matching files (`dev_rules.slice_micro_rules`).

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
