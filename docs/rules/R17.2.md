# R17.2: No server-only code in client

Group: React and Next.js patterns. Generated from the rule definitions; do not edit by hand.

## What it catches

No server-only code in client: 'server-only' imports barred from client-marked components.

## Why

A server-only module in client code leaks secrets or fails the build.

## A bad example

```tsx
'use client';
import 'server-only';
```

## A good example

```tsx
// keep the import in a server file and pass the data down
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
