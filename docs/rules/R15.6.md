# R15.6: Empty state affordance

Group: Error boundaries and fallback rendering. Generated from the rule definitions; do not edit by hand.

## What it catches

Empty state affordance: data tables and lists display actionable empty state message.

## Why

An empty table with no message looks broken.

## A bad example

```tsx
{rows.map(Row)}
```

## A good example

```tsx
{rows.length ? rows.map(Row) : <Empty action={<AddButton />} />}
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

There is no ignore comment. That is on purpose: a comment that silences a rule is the easiest way for an automated author to pass its own gate. Fix the code instead.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
