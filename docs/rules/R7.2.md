# R7.2: Granular field validation

**Short answer:** Return field-level errors and preserve user form inputs. One generic error forces the user to guess and to retype the whole form.

Group: Architecture and contracts. Status: stable. Generated from the rule definitions; do not edit by hand.

Playground: <https://brevio.pro/tools/agent-guard-playground?rule=R7.2>

## What it catches

Granular field validation: return field-level errors and preserve user form inputs.

## Why

One generic error forces the user to guess and to retype the whole form.

## A bad example

```ts
return { error: 'invalid' };
```

## A good example

```ts
return { errors: { email: 'Enter a valid email' } };
```

## How it is checked

- Nothing yet. No scanner and no slice card checks it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R7.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its definition in `dev_rules.py` or `code_rules/__init__.py`. That is a code change and is reviewed like one.
